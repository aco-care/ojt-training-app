## 実装確認の方法(AI向け・重要)

**AIが機能を実装したら、ユーザーに手動確認を頼む前に、必ずAI自身がテストアカウントでブラウザ操作して確認すること。**

- パスワードをログインフォームに入力する操作は方針上禁止(誰のアカウントであっても)。そのため以下の方法でログインする:
  1. 確認用テストアカウントが未作成なら、Supabase管理API(service role key、`.env.local`にあり)経由で作成する。例: `role: 'supervisor'`, 対象拠点の`facility_id`, `profile_facilities`に1行追加。
  2. `supabase.auth.admin.generateLink({ type: 'magiclink', email })` で `hashed_token` を取得する(送信はされない、その場で取得できる)。
  3. ブラウザで `http://localhost:3000/auth/callback?token_hash=<hashed_token>&type=magiclink` に直接アクセスする。パスワード入力なしでセッションが確立する(`/auth/set-password`に飛ぶが無視してそのまま他のページへ遷移してよい)。
  4. トークンは使い捨てなので、ログインし直す場合は2から再実行する。
- 確認用テストアカウント(2026-08-14作成、削除せず保持): `qa-test-fukinohanare@ojt-training-app.internal` / 名前「【QAテスト】ふきのはなれ確認用」/ role: supervisor / 所属: 複合型サービス ふきのはなれ。他拠点の確認が必要な場合は`profile_facilities`に行を追加するか、同様の手順で別アカウントを作る。
- 確認時は実データを汚さないよう、フォーム送信(作成・削除等の書き込み)は行わず、入力内容の表示確認に留めること。書き込みテストがどうしても必要な場合はユーザーに確認する。
- ローカル開発サーバー(`localhost:3000`)と本番(`ojt-training-app.vercel.app`)は同じ本番Supabaseに接続しているが、フロントエンドのコードは別(ローカルは未デプロイの最新コード)。動作確認は必ずローカルで行うこと。
